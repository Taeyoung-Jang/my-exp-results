# Session 01 – Sprint Planning for Migration Initiative (2022‑06‑15)

## Overview
A concise guide on turning a large “moving parts” migration project into a focused sprint, ending with a concrete one‑page migration‑plan deliverable.

## Core Approach
- **Treat the migration as a separate track** – isolate it from regular sprint stories. [[concepts/migration-track]]
- **Define clear milestones** – break the initiative into tangible checkpoints (e.g., contract validation, mapping, cutover). [[concepts/milestone-based-sprint-planning]]
- **Pull only the next milestone into the sprint** – keeps work visible but limited.
- **Capacity‑cap the migration work** – reserve ~12‑15 story points (≈30 % of a 40‑point sprint) for the migration track. [[concepts/capacity-capping]]
- **Make progress visible** – stand‑up checks: *current → next → blocked?*.

## Sprint Goal (Finalized Migration Plan)
Produce a complete, review‑ready migration plan that includes:
- Mapping decisions
- Cutover sequencing
- Risk handling
- Sign‑off requirements

## Current Milestone
“Validate the new API contract and data mappings in a controlled environment” (or, when tightened, “Finalize the migration plan”).

## Backlog Items (5‑8 items)
1. Draft migration‑plan document following the team template.  
2. Add a data‑mapping appendix with field‑by‑field changes.  
3. Create a cutover playbook (steps, owners, success checks).  
4. Review draft with integration lead and capture revisions.  
5. Obtain external sign‑off from the client’s technical contact.  
6. Compile a risk & dependency summary.  

Each item includes a *Definition of Done* that specifies the artifact, verification, and owner.

## Required Artifacts
- Finalized migration plan (linked from [[entities/confluence]])  
- Mapping appendix  
- Cutover playbook  
- Risk & dependency summary  

All artifacts are linked from a single Confluence page.

## Sign‑off Process
- Internal approval by the integration lead.  
- External confirmation by the client’s technical contact.

## Next Milestone (Post‑Sprint)
Rehearse cutover steps in staging and perform end‑to‑end migration validation.

## Takeaways
- Isolate large initiatives into their own track.  
- Use milestone granularity to keep work manageable.  
- Explicitly cap capacity to protect regular sprint flow.  
- Define clear artifacts and sign‑off criteria for migration planning.
