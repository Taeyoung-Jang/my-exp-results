# Urgent Request Triage Rule

## Definition
The Urgent Request Triage Rule is a quick, two‑question filter that helps you determine whether an incoming request must interrupt your deep‑work time or can be deferred to an afternoon slot.

## Decision Questions
1. **Does this block someone else’s progress right now?**
2. **Does it need my creative or technical input immediately?**

- **If both answers are *yes***, treat the request as **urgent** and address it right away.
- **If either answer is *no***, place the request in your same‑day afternoon queue.

### Optional extra filter
*Will handling this request now significantly improve the project’s outcome or timeline?* If the answer is *no*, keep it in the queue.

## Quick Response Script
You can copy‑paste this message when a request pops up during your morning deep‑work block:
```
Got this! I’m in a focused work block at the moment, but I’ll review it this afternoon and get back to you. If this is blocking anything urgent on your end, just let me know.
```

## How It Fits With Your Workflow
- Protects the **[[concepts/deep_work]]** period by limiting interruptions.
- Works hand‑in‑hand with a **[[concepts/weekly_dashboard]]** that tracks pending afternoon tasks.
- Aligns with the broader **[[concepts/triage_rule]]** approach to prioritising work.
