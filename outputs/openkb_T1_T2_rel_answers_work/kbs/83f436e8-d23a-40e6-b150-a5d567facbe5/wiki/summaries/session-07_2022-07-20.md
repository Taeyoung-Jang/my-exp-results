# Summary of Session 7 (2022‑07‑20)

**Topic:** Helping the user articulate a technical‑individual‑contributor (IC) career path, define concrete goals, craft review‑ready OKRs, and set up lightweight progress tracking.

---

## 1. Communicating an IC Track Ambition
- Emphasize **deep technical impact** rather than lack of ambition.
- Position the goal as **technical leadership without management** (see [[concepts/technical-leadership-without-management]]).
- Use conversational language tailored to the manager’s attitude (supportive vs. pushing toward management).

### Conversational 1:1 Scripts
- **Supportive manager** – “I’m energized by deep technical work and want to keep growing as an IC.”
- **Manager nudging to management** – “I appreciate the leadership confidence, but I’m at my best solving complex systems; I’d like to stay on the IC track” (see [[concepts/ic-track-ambition]]).

## 2. Performance‑Review Bullet Examples
- Demonstrated strong IC‑track ambition by driving high‑impact technical decisions without moving into people‑management.
- Grew technical scope by owning key [[entities/distributed-systems]] components and delivering measurable reliability improvements.
- Provided technical leadership through design proposals, mentoring, and establishing best practices.

## 3. Concrete Goal Sets (12–18 months)
### Backend / Distributed‑Systems Engineer
1. Redesign a high‑traffic service → 20‑30 % latency reduction, 40 % throughput gain.  
2. Own a critical component (caching, replication) → introduce reliability mechanisms and mentor peers.  
3. Build end‑to‑end observability → reduce debugging time by ≥30 %.

### Platform / Infrastructure Engineer
1. Lead reliability initiative → cut fleet‑wide incident recurrence by 20‑30 %.  
2. Deliver auto‑remediation system → resolve a major failure class without human intervention.  
3. Improve efficiency → reduce compute/storage cost by 10‑20 % while keeping SLA.

## 4. Review‑Proof OKR Refinement
### Distributed‑Systems OKR
- **Objective:** Strengthen reliability and performance of the core workflow while increasing my technical ownership.
- **Key Results:**
  - Drive latency improvements to achieve a 25 % reduction in p99 latency.
  - Lead reliability work that drops related incident volume by 30 %.
  - Deliver two design proposals adopted by the team.
  - Publish onboarding docs making me the primary point of contact.

### Platform/Infrastructure OKR
- **Objective:** Increase platform reliability and efficiency through a high‑impact infrastructure initiative.
- **Key Results:**
  - Cut recurring platform incidents by 20‑25 % via root‑cause fixes and automation.
  - Implement an auto‑recovery mechanism that resolves a major failure class autonomously.
  - Reduce compute/storage cost by 10‑15 % while meeting SLA.
  - Define and meet SLOs >99.9 % availability for two consecutive quarters.

*(All KRs are framed for [[concepts/review-proof-okrs]])*

## 5. Evidence Collection for Review‑Proofing
- **Dashboards:** Before/after latency, throughput, cost, and availability charts.  
- **Incident Metrics:** Weekly incident counts, severity, MTTR – exported from SRE tools.  
- **Design Docs:** Links with timestamps, approval comments, and adoption notes.  
- **Adoption Metrics:** Number of engineers using new standards, PRs merged that reference the docs.  
- **Ownership Logs:** A running doc or folder storing screenshots, release notes, and a brief “what I delivered” log.

## 6. Monthly Check‑In Template (lightweight)
```
Subject: Monthly IC‑track Goal Update – [Month]

Hi [Manager Name],

**What I shipped this month**
- Bullet of shipped feature / design doc (include link)
- Metric movement (e.g., latency ↓ 22 %, incidents ↓ 18 %).

**What I led / owned**
- Brief note on architecture decisions, mentoring sessions, or automation built.

**What’s next**
- Key actions for the upcoming month aligned to the OKRs.

Thanks,
[Your Name]
```
