# Summary of session-02_2024-06-15

This conversation provides a practical framework for deciding when to install software updates and, more specifically, how to manage *beta‑first* update workflows on phones and laptops.

## Update timing strategy
- Adopt a **middle‑of‑the‑road** approach: wait a few days after release to allow early bugs to surface, unless the update fixes a critical security vulnerability.
- Weigh **feature importance**, **security impact**, and **early user feedback** when choosing a rollout schedule. See [[concepts/software-update-strategy]].

## Beta‑testing risk reduction
- **Device isolation**: use secondary hardware (spare phone, tablet, or secondary computer) for risky betas; keep primary devices free of experimental software. See [[concepts/device-isolation]].
- **Non‑negotiable habits** for beta‑first users:
  1. Perform a fresh, verified backup immediately before any beta install.
  2. Have a memorised **rollback plan** that can be executed in under an hour.
  3. Separate core workflows from beta environments via distinct user accounts or separate devices. See [[concepts/beta-testing-risk-management]].

## Backup checklist
1. **Phone**: ensure [[entities/icloud]] or [[entities/google-drive]] backup is current, then create a manual local backup to a computer.
2. **Laptop**: run a full‑disk image using [[entities/time-machine]] (macOS) or [[entities/file-history]] (Windows).
3. **Verification**: check timestamps, confirm backup file existence, and briefly open the restore interface to ensure validity.

## Rollback plan
- **Phone**: know how to enter recovery mode and restore from the local backup.
- **Laptop**: know how to boot into the recovery environment and restore the latest system snapshot.
- Practice the steps periodically to keep them muscle‑memory level.

## Checklist for beta installs (phone + laptop)
- Fresh full backup → verify backup → review rollback steps → install beta → monitor for issues.
- If problems arise, revert using the prepared rollback path.

## Separation of “beta life” and “daily driver”
- **Secondary hardware** is ideal; otherwise:
  - Create a dedicated **beta user account** on the laptop for experimental apps.
  - Keep essential apps (banking, work authentication) on the stable account or a separate device.
  - Avoid enrolling critical phone apps in beta programs.
