## Summary of session-38_2024-12-13

This document outlines a **7‑hour weekly study plan** for a Python learner, combining practice problems, two small projects (an API‑driven weather tool and a JSON‑based habit/bookmark tracker), a reusable session checklist, and a sample learning‑log entry.  

### Weekly schedule (7 h total)
- **Monday – 1 h practice** – core [[entities/python]] exercises for the week’s concepts.  
- **Wednesday – 1 h practice** – a different topic to keep skills fresh.  
- **Friday – 3 h API project** – build a command‑line [[entities/open-meteo]] weather fetcher (includes geocoding via Open‑Meteo’s free geocoding endpoint).  
- **Sunday – 2 h file‑based project** – create a JSON‑backed habit tracker or bookmark manager.  
- **End‑of‑week 10 min review** – reflect on wins, obstacles, and next steps.

### Project outlines
- **API project (Open‑Meteo)**
  1. Write a `geocode_city` function to convert a city name to latitude/longitude using Open‑Meteo’s geocoding endpoint.  
  2. Implement `fetch_weather` to request current temperature data using the [[entities/requests]] library.  
  3. Parse the JSON response (`parse_temperature`) and display a clean CLI summary.  
  4. Add basic error handling for missing locations or unavailable data.  

- **File‑based project (JSON)**
  - Use a simple schema: a list of objects with fields like `name`, `date`, and `done` (habit tracker) or `title`, `url`, `tags` (bookmark manager).  
  - Provide `load_data`, `save_data`, and `add_entry` helpers.  
  - CLI prompts for adding or listing entries.  

### Reusable checklist (start / end of each session)
- **Start**: What am I focusing on? What’s the smallest goal?  
- **End**: What did I complete? What confused me? What to tackle next?

### Sample log entry
```
Today I practiced list comprehensions, struggled with condition order, but it clicked after a few examples. In the API project I fetched weather data and parsed JSON, though handling missing fields took longer. Next time I’ll review error‑handling and add simple caching.
```

### Choosing JSON vs CSV for file‑based projects
- **[[entities/json-format]]** – best for hierarchical or multi‑field records (habit tracker, bookmarks).  
- **[[entities/csv-format]]** – simpler for flat, tabular data.
