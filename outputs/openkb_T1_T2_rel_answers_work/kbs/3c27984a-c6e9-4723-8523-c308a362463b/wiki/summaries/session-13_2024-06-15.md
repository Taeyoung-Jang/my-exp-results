## Summary

- Comparison of **local hardware** vs **cloud resources** for compute‑heavy simulations.  
- Break‑even utilization approx 50‑60% sustained usage; above this local tends to be cheaper.  
- **Hidden costs** on local: electricity, cooling, floor space, hardware replacement, admin time, downtime. [[concepts/hidden-costs]]  
- **Hidden costs** on cloud: storage fees, data egress, specialized hardware premiums, licensing. [[concepts/hidden-costs]]  
- Framework for cost estimation: annualized local cost (purchase amortization + power + cooling + admin + downtime) → effective $/hour; cloud cost = instance hourly rate + storage + egress per job. [[concepts/cost-analysis]]  
- Recommendation pattern: hybrid – baseline **[[entities/local-workstation]]** for nightly batches, burst to **[[entities/cloud-compute]]** (e.g., **[[entities/gpu-instance]]**) for occasional spikes.  
- Top 3 decision metrics: queue wait time, utilization level, data transfer/egress volume. (decision metrics)  
- Proposed automated **bursting rule**: if predicted queue delay > X hours *or* utilization > Y% for Z hours, dispatch job to cloud. (bursting rule)  
- Estimating marginal cloud cost per job: instance rate × runtime + temporary storage cost + result egress cost. (cost estimation)  
- Strategies to avoid egress charges: keep large intermediates in cloud, download only summaries, use cloud‑side post‑processing, maintain a durable cloud bucket for burst workload. (egress avoidance)

**Key concepts**: [[concepts/cost-analysis]], [[concepts/utilization-break-even]], [[concepts/hidden-costs]].
