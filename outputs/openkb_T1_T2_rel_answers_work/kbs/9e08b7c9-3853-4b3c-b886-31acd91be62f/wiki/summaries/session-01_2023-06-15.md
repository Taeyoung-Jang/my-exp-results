## Summary of Session 1 (2023-06-15)

The assistant advises developers that **the core of a strong professional presence is verifiable, end‑to‑end code**. All other signals (portfolio site, blog, social profiles) are useful only as wrappers around that work.

### Core Recommendations
- **Start with a solid project** on GitHub that demonstrates the full development lifecycle.
- **Polish the GitHub surface** before adding other channels. This includes:
  - Selecting 3‑6 high‑impact repos to pin.
  - Adding concise one‑sentence descriptions to pinned items.
  - Maintaining clean, focused README files.
  - Adding screenshots/GIFs, tidying repo structure, and optional `CONTRIBUTING` notes.
  - Updating the profile README with a brief intro and key links.  
  See [[concepts/github-surface-polish]] for details.

### README Template for Recruiters
1. **One‑sentence project summary**
2. **Problem statement & why it matters**
3. **How it works** – brief architecture/decision overview
4. **Getting started** – minimal run commands
5. **Tech stack & notable design choices**
6. *(optional) Screenshot/GIF*
7. *(optional) Future work / limitations*  

Use the checklist in [[concepts/readme-checklist-recruiters]].

### Portfolio & Blog Guidance
- After GitHub polishing, create a **lightweight portfolio page** that curates the highlighted repos. No need for elaborate design.
- Blog posts are **optional**; write them only if you enjoy explaining decisions or want to showcase thought process.

### Scoring Rubric for Pinning Repos
Evaluate each repo on three dimensions (1‑5 points each):
1. **Relevance** – fit with target job roles.
2. **Impact** – technical depth, real‑world usage, problem complexity.
3. **Clarity** – ease of understanding for a quick skim.

Sum the scores; the highest‑scoring repos become the pinned selection. See [[concepts/repo-scoring-rubric]] for the full rubric.
