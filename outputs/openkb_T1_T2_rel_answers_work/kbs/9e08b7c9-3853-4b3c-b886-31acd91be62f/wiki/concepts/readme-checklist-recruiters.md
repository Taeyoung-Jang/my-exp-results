# README Checklist for Recruiters

A focused README helps recruiters assess a project at a glance.  The checklist originated from the advice given in [[summaries/session-01_2023-06-15]] and outlines the minimal sections that should be present, the order they should appear in, and optional visual enhancements.

## Core Sections (must‑have)
1. **One‑sentence project summary** – a clear, high‑level description placed at the very top.
2. **Problem statement & relevance** – a short paragraph explaining the real‑world problem the project solves and why it matters.
3. **How it works** – a brief overview of the architecture or key design decisions, written for a non‑technical skim.
4. **Getting started** – the absolute minimal commands needed to run or build the project (e.g., `git clone`, `npm install`, `docker run`).
5. **Tech stack & notable choices** – bullet list of primary languages, frameworks, and any distinctive design patterns.

## Optional Enhancements (nice‑to‑have)
- **Screenshot or GIF** – visual proof of the UI or output.
- **Future work / limitations** – a short note on what could be improved or known constraints.
- **CONTRIBUTING or NOTES** – if the repo is meant for collaboration, a brief guide for external contributors.

## Styling Tips
- Keep paragraphs short; use bullet points where possible.
- Use markdown headings (`##`) to separate sections so recruiters can jump with a skim.
- Highlight key numbers (e.g., "10k+ weekly users") to convey impact quickly.

## Relationship to Other Concepts
- This checklist is part of a broader effort to **polish the GitHub surface** – see [[concepts/github-surface-polish]].
- It aligns with the **repo scoring rubric** used to prioritize which repositories to pin; a well‑crafted README boosts the *Clarity* score in [[concepts/repo-scoring-rubric]].
