# Polishing the GitHub Surface

**Definition**: Streamlining a developer's GitHub presence—pinned repos, profile README, and repo README files—to make the work instantly understandable and attractive to recruiters.

## Core Elements
1. **Pinned Repositories**
   - Choose 3‑6 repos that showcase a range of relevant skills.
   - Add short, clear one‑sentence descriptions for each pinned repo.
2. **Repo README Improvements**
   - Follow a concise outline that recruiters skim (project summary, problem statement, high‑level architecture, quick start, tech stack, optional screenshot/GIF, future work).
   - Include screenshots or short demos where appropriate.
   - Keep the repository structure tidy; remove unused files.
   - Add a brief `CONTRIBUTING` or `NOTES` section if collaboration details matter.
3. **Profile README**
   - Write a brief intro that highlights your core strengths and links to the pinned repos.
   - Use clear language and avoid excessive jargon.

## Why It Matters
Recruiters typically spend less than a minute on a candidate’s GitHub. A polished surface lets them **immediately grasp**:
- What the project does.
- Why it’s interesting or impactful.
- The candidate’s technical breadth.

## Checklist (derived from [[concepts/readme-checklist-recruiters]])
- Pin strongest repos.
- Add concise descriptions to pins.
- Ensure each repo has a clean README following the recruiter‑focused outline.
- Include visual aids (screenshots/GIFs).
- Keep repo structure clean.
- Provide a short CONTRIBUTING/NOTES if relevant.
- Update the profile README with an overview and key links.

## Relationship to Scoring
To decide which repos to pin, apply the [[concepts/repo-scoring-rubric]] (relevance, impact, clarity) and select the highest‑scoring ones.
