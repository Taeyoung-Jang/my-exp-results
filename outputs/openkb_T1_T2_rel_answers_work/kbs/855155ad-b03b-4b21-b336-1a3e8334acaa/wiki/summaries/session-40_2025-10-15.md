## Summary of Session 40 (2025‑10‑15)

**Purpose**: Provide practical methods for structuring a physical and digital workspace to maximise [[concepts/deep_work_environment]], and a concrete offline overnight compute workflow that is robust, crash‑safe, and easy to resume.

### 1. Workspace & Routine Design
- **Environment guardrails**: keep only the current project visible, use a second machine or server for long runs, and silence notifications.
- **Daily blocks**: start each block by launching jobs, noting next steps, and then enforce a distraction‑free period.
- **Reliability habits**: use scripts, log everything, and write progress markers so you don’t need to babysit.
- **End‑of‑day reset**: clear the desk, leave a one‑sentence reminder, and ensure all jobs are queued.

### 2. Offline Overnight Compute Workflow
- **Goal**: run heavy jobs on a disconnected machine, then transfer results once per day.
- **Key steps**: create a dated run folder, snapshot code/config, launch sequential jobs, log in a single file, checkpoint, and bundle outputs for USB transfer. This follows the [[concepts/offline_compute_workflow]] pattern.

### 3. Folder Layout & Naming Convention
```
<run_root>/
│   run.log               # unified log
│   status.json           # completed stages
│   bundle/               # transfer package
├── config/               # config files for the run
├── code/                 # frozen snapshot of scripts (git hash or copy)
├── checkpoints/          # intermediate saves
└── outputs/              # final artifacts
```
- Run folder name: `YYYY-MM-DD_<tag>` (e.g., `2026-03-17_mesh-exp`).
- All outputs, logs, and status live inside this folder for easy review.

### 4. Bash Script Skeleton (initial version)
```bash
#!/usr/bin/env bash
set -euo pipefail

TAG="$1"
DATE="$(date +%Y-%m-%d)"
RUN="runs/${DATE}_${TAG}"
mkdir -p "$RUN"/{config,code,checkpoints,outputs,bundle}
# ... snapshot code, copy config, define log function ...
run_job "stage1"
run_job "stage2"
run_job "stage3"
# ... prepare bundle ...
```
- Handles code snapshot, config copy, sequential job execution, and bundle creation.

### 5. Crash‑Safe, Resume‑Friendly Enhancements
- **Lockfile** prevents concurrent runs; linked to the [[entities/run_lock]] entity.
- **Signal traps** ensure lock removal on exit.
- **status.json** records completed stages.
- Script skips stages already marked as done.

#### Enhanced Script Highlights
```bash
LOCK="$RUN/run.lock"
if [ -e "$LOCK" ]; then echo "Run locked"; exit 1; fi
echo $$ > "$LOCK"
trap 'rm -f "$LOCK"' EXIT INT TERM

# initialise status
[ -f "$STATUS" ] || echo '{"completed": []}' > "$STATUS"

completed() { jq -r '.completed[]' "$STATUS" | grep -Fx "$1" >/dev/null; }
mark_done() { jq ".completed += [\"$1\"]" "$STATUS" > tmp && mv tmp "$STATUS"; }
```

### 6. Example `status.json`
```json
{
  "completed": ["stage1", "stage2"]
}
```
- The morning review can simply run `jq '.completed' status.json` to see progress.

### 7. Morning Review Routine
1. Mount the USB drive (see [[entities/usb_transfer]]) and copy the `bundle/` folder.
2. Open `run.log` and skim for `JOB_FAIL` or duration anomalies.
3. Inspect `status.json` to confirm which stages finished.
4. Archive the run folder on the main machine and plan next actions.
