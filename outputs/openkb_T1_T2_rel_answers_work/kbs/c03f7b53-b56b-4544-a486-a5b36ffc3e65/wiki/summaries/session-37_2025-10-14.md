# Summary of Session 37 (2025‑10‑14)

## Trade‑offs: Cloud‑linked vs Local Windows account
- **Cloud‑linked account**: boosts convenience (settings sync, automatic recovery, password sync) but reduces privacy and can introduce opaque sync‑related failures.  
- **Local account**: maximizes privacy and predictability; failures are isolated to the device. Requires manual handling of backups, password sync, and recovery.  
- Overall recommendation for a stability‑focused user: keep the core login **local** and layer on only the needed cloud features.

## Concrete Windows 11 Checklist
### 1. Backup strategy
- **Full system image** on an external drive (Windows 7 Backup & Restore). Handles disaster recovery and restores BitLocker/TPM state on the same hardware. [[concepts/system-image-backup]]
- **Off‑site file backup** for irreplaceable data (documents, photos). Use a cloud drive or self‑hosted sync (e.g., Syncthing) targeting specific folders only. [[concepts/offsite-backup]] [[entities/syncthing]]
- **Optional File History** for versioned copies of selected folders; useful for accidental overwrites but not a full recovery solution. [[entities/file-history]]

### 2. Password management
- Choose a standalone password manager that syncs independently of Windows login:
  - **Bitwarden** (cloud‑based vault) [[entities/bitwarden]]
  - **1Password** (cloud‑based vault) [[entities/1password]]
  - **KeePassXC** + cloud folder or Syncthing (self‑hosted) [[entities/keepassxc]]
- None of these “take over” the Windows credential store. [[concepts/password-manager]]

### 3. BitLocker & TPM
- When using BitLocker on a local account, the recovery key **does not auto‑upload** to a Microsoft profile.
- Manually save the recovery key to:
  1. A USB drive stored safely
  2. An encrypted note in your password manager
- Restoring a system image on the same hardware usually boots without a key prompt; hardware changes (new motherboard, firmware) will trigger a recovery‑key prompt. [[entities/bitlocker]] [[entities/tpm]]

## Recommendation: System image vs File History
- For a non‑technical, stability‑oriented user, **pick the system image**. It provides a full‑machine “restore to working state” without needing Windows to boot first. File History is supplementary for file‑level versioning. [[concepts/system-image-backup]]

## Summary of Benefits
- **Privacy**: No continuous cloud identity linkage.
- **Stability**: Failures are localized; recovery relies on deterministic backups.
- **Selective Convenience**: Cloud storage only for chosen folders; password manager provides cross‑device passwords without exposing the Windows login.
- **Safety net**: System image + off‑site file backup + secure BitLocker key storage ensures recoverability. [[concepts/backup-strategy]] [[concepts/encryption]] [[entities/windows-11]] [[entities/windows]]
