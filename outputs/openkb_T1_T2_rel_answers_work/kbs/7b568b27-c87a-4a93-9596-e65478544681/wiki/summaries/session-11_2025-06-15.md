## Summary of session‑11_2025‑06‑15

The conversation proposes a **simple, search‑driven local file system** and a **two‑layer backup plan** that requires minimal ongoing effort, especially for [[entities/windows-11]] users.

### Core ideas
- **Folder hierarchy**: a handful of broad top‑level folders – `Documents`, `Media`, `Projects`, `Inbox`, and `System` – each with a shallow sub‑structure (e.g., `Media/Photos/2024/2024‑03 Trip to Seattle`). The design favours intuition over exhaustive taxonomy and aligns with [[concepts/local-file-organization]].
- **Naming convention**: place the date first when time matters, followed by a concise description (e.g., `2024‑03‑12 Client‑Proposal‑Acme.docx`). Use plain English for non‑date‑critical items. Consistent names make native OS search reliable.
- **Inbox workflow**: new files land in an `Inbox` folder and are periodically sorted, keeping daily work friction‑free.

### Backup strategy (offline, no cloud)
1. **Drive A – primary automatic backup**
   - Enable **File History** for user folders, set to keep versions indefinitely and run at the shortest interval allowed. This is [[entities/file-history]].
   - Provides continuous **versioning** and quick recovery from accidental deletion or ransomware edits. See [[concepts/versioning]].
2. **Drive B – secondary offline safeguard**
   - Use **Windows Backup and Restore (Windows 7)** to create a full **system image** weekly (or bi‑weekly). This tool is [[entities/windows-backup-restore]].
   - The drive stays unplugged most of the time, protecting the image from ransomware. Refer to the physical storage as an [[entities/external-drive]] (or a home NAS, but only the external‑drive link is whitelisted).

### Maintenance cadence
- Drive A runs unattended; only occasional checks of File History settings are needed.
- Plug Drive B in once a week (or every two weeks) to perform the scheduled system image, then unplug.
- Periodically tidy the `Inbox` folder.

### Risks & mitigations
- **Ransomware**: offline Drive B prevents malware from corrupting the backup copy.
- **Drive failure**: two independent physical drives ensure redundancy.
- **Versioning**: handled by File History, preserving multiple historical states of each file (see [[concepts/versioning]]).
