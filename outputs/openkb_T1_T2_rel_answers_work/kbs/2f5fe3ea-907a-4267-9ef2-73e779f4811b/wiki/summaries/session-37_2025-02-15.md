# Summary of session‑37 (2025‑02‑15)

- **Goal**: Set up a simple, low‑maintenance, reasonably secure personal hub for files and notes that works across devices and isn’t tied to any single cloud provider. See [[concepts/self-hosted-home-hub]].

- **Core recommendation**: Use **[[entities/syncthing]]** for peer‑to‑peer file synchronization combined with a lightweight web file browser such as **[[entities/file-browser]]** (or a minimal server like *miniserve*) for LAN access. This satisfies [[concepts/low-maintenance-file-sync]] and supports [[concepts/cross-device-syncing]].

- **Remote access**: Prefer a VPN solution such as **[[entities/tailscale]]** or **[[entities/wireguard]]** over exposing HTTPS directly; this reduces the attack surface and eliminates the need for certificate management.

- **Notes handling**: Keep notes as plain Markdown files. Edit or view them with browser‑based editors like **[[entities/stackedit]]** or **[[entities/editor-md]]**, or serve the folder via a static‑site generator.

- **Browsing / search**: Generate a static site from the Markdown notes using tools such as **[[entities/mdbook]]** or **[[entities/mkdocs]]** (watch mode) and serve it with your existing web server. Alternatively, use a tiny server like *markdown‑server* together with a client‑side search library (e.g., Lunr.js) for fast, read‑only navigation. See [[concepts/client-side-search]].

- **Maintenance**: All suggested components run as single binaries, require only occasional updates, and operate on the existing plain‑folder structure that is already backed up nightly.
