# Client‑Side Search

Client‑side search refers to the technique of performing full‑text indexing and query processing entirely in the user's browser, usually via a JavaScript library such as **Lunr.js**. This approach eliminates the need for a dedicated backend search service, keeping the system lightweight, secure, and easy to maintain.

## Why use client‑side search?
- **Low maintenance** – No server‑side index or database to manage.
- **Privacy‑friendly** – Search queries never leave the user's device.
- **Simple deployment** – Works with any static site or file server.

## Application in a self‑hosted home hub
In the context of a personal file and note hub (see [[summaries/session-37_2025-02-15]]), client‑side search is an ideal complement to a static‑site setup generated by tools like [[entities/mdbook]] or [[entities/mkdocs]]. After generating the HTML site from plain Markdown notes, a small JavaScript bundle can be added to enable instant search across all notes without additional server components.

## Typical implementation steps
1. **Generate a static site** from your Markdown notes using a tool such as [[entities/mdbook]] or [[entities/mkdocs]] in watch mode.
2. **Add a JavaScript search library** (e.g., Lunr.js) to the site.
3. **Create an index** of the Markdown content during the build step; the index is served as a JSON file.
4. **Integrate a search UI** on the site that queries the JSON index in the browser.

## Benefits for a low‑maintenance, self‑hosted hub
- Fits naturally with a **self‑hosted home hub** (see [[concepts/self-hosted-home-hub]]) that prioritizes simplicity and security.
- Aligns with the **low‑maintenance file sync** philosophy (see [[concepts/low-maintenance-file-sync]]) by avoiding extra services.
- Supports **cross‑device syncing** of notes via tools like [[entities/syncthing]], as the search index is regenerated automatically when files change.
