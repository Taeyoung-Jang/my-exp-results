# Definition of Done

**Overview**

Definition of Done (DoD) is a lightweight, one‑sentence checklist that specifies exactly what must be finished before a work item can be considered complete and handed off to the next person. It is designed to be visible where the work lives, so the signal is instantly understood without extra meetings.

**Why it matters**

- Removes ambiguity when the team is busy or when a newcomer steps in.
- Provides a clear, repeatable handoff point that aligns with the team's existing workflow.
- Serves as a backup language for the tacit knowledge that veteran crews rely on.

**How to craft a DoD**

1. Identify the typical stages of your workflow (e.g., design, review, implementation).
2. For each stage, write a single‑sentence checklist covering:
   - Where the final artefact is stored (e.g., shared folder).
   - What documentation or notes must be updated.
   - How to note any remaining blockers.
3. Keep the checklist short—no more than two or three bullet points—so it is read and respected.

**Embedding DoD in tools**

- **Trello**: Place the DoD text in the card description or a custom checklist field. Example from [[summaries/session-04_2024-06-16]]:
  ```
  Done when:
  - files are in the shared folder
  - notes are updated in the card
  - blockers are listed (if any)
  ```
- **Slack**: Use a matching one‑liner message that references the completed DoD and signals the handoff (see [[concepts/handoff-signal]]).

**Benefits**

- **Visibility** – Everyone can see the criteria at a glance.
- **Consistency** – The same definition applies across all similar tasks.
- **Scalability** – New team members or temporary fills can follow the same simple rule.

**Related concepts**

- [[concepts/handoff-signal]] – the action that indicates the DoD has been met.
- [[concepts/role-ownership]] – clarifies who is responsible for meeting each DoD.
