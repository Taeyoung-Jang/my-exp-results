# Summary of Session 10 (2024‑06‑15)

## Overview
This conversation provides a practical checklist for updating or auditing a personal address across a wide range of accounts, and supplies two spreadsheet‑style templates that focus on **preventing accidental address changes** (e.g., loss of unit number or ZIP+4) while allowing the user to prioritize based on the purpose of each address entry.

## Key Concepts
- **[[concepts/address-audit]]** – a systematic review of every service that stores your address.  
- **[[concepts/address-risk-prioritization]]** – classifying accounts by purpose (billing, shipping, legal) to decide which mismatches are critical.  
- **[[concepts/usps-formatted-address]]** – using the official USPS‑verified version (including ZIP+4 and unit) as the single source of truth.  

## Checklist for a Full Address Update (move scenario)
1. **Identity & legal** – government IDs, employer, banks, credit cards, loans, insurance, tax agency.  
2. **Day‑to‑day services** – online shopping, food delivery, streaming/subscriptions, memberships.  
3. **Medical & pharmacy** – update prescriptions early.  
4. **Mail forwarding** – enable a buffer period before and after the move; keep active for ~2 months.  
5. **Package handling** – temporarily hold or redirect shipments that are scheduled around the move date.

## Quiet “Address Health Check” (no move)
- Create an **authoritative USPS‑verified address** (copy from [[entities/usps]] lookup).  
- Compare each account’s stored address against this reference without making changes unless a genuine mismatch is found.  
- Verify both **visual representation** (web UI) and **printed artifacts** (bills, shipping labels, wallet apps).  
- Note any vendor‑side auto‑formatting; only correct when structural fields (unit, ZIP+4) are altered.

## Auditing Template – Version 1
| Column | Purpose |
|--------|---------|
| Account Name | Service/provider name |
| Address on File (Exact Copy) | Literal address shown in the account |
| USPS‑Verified Address | Reference address for this row |
| Match Status | “Exact match”, “Formatting only”, “Needs correction” |
| Unit Present? | Yes/No |
| ZIP+4 Correct? | Yes/No |
| Vendor Reformatting Behavior | Notes on auto‑changes (e.g., drops unit) |
| Last Checked | Date |
| Notes | Additional observations |

## Enhanced Template – Version 2 (focus on accidental changes & risk)
| Column | Purpose |
|--------|---------|
| Account Name |
| Address Purpose | Billing / Shipping / Legal / Verification / All |
| Address on File (Exact Copy) |
| USPS‑Verified Address |
| Critical Fields Intact? | Yes/No (unit & ZIP+4) |
| Formatting Only? | Yes/No (punctuation, abbreviations) |
| Vendor Auto‑Changes? | Description of observed rewrite behavior |
| Risk Level | High (legal/billing), Medium, Low |
| Last Checked |
| Notes |

The second version adds **risk prioritization** so high‑impact accounts (legal notices, billing) are audited first, and a dedicated column flags whether the vendor is silently rewriting the address.

## Takeaway
By anchoring every check to a [[concepts/usps-formatted-address]] and using a structured template that records both *what* the address looks like and *how* the vendor may transform it, you can confidently keep all records accurate without triggering unwanted forwarding or shipment disruptions.
