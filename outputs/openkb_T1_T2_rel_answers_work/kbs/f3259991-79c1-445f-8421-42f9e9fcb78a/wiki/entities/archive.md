## Archive (Top‑Level Folder)

**Type:** other

The **Archive** folder is a top‑level bucket intended to store items that are no longer actively used but still need to be retained for reference or compliance. In the guidance from [[summaries/session-10_2025-06-15]], Archive serves as the destination for:

- Completed projects moved from `Work/Projects` to `Work/Archive` (or `Archive/OldProjects`).
- Old personal files that are no longer current, such as `Archive/OldPersonal`.
- Any other content that has been superseded or is dormant.

### Key Characteristics
- **Purpose:** Keeps the active workspace (e.g., `Work`, `Personal`, `Finances`, `Media`, `Reference`) uncluttered by separating finished work from ongoing work.
- **Boundary Rule:** Only items that are truly inactive belong here; anything still in regular use should remain in its primary top‑level folder.
- **Structure:** Often organized into sub‑folders like `OldProjects`, `OldPersonal`, or by year/category to aid occasional retrieval.
- **Interaction with Naming Conventions:** Files retain their original naming pattern (e.g., `ProjectName_2026-03`) to preserve chronological context, aligning with [[concepts/naming_conventions]].

### Related Concepts and Entities
- Part of the overall [[concepts/folder_hierarchy]] that defines how top‑level buckets relate to one another.
- Works alongside other top‑level entities such as [[entities/work]], [[entities/personal]], [[entities/finances]], [[entities/media]], [[entities/reference]], and [[entities/apps_utilities]].

### Practical Use
When a project reaches completion, move the entire project directory from its active location (e.g., `Work/Projects/ClientA_ProjectName_2026-03`) to `Work/Archive` or `Archive/OldProjects`. This single move preserves all associated files without creating duplicate copies, supporting a clean separation of active versus completed work without redundancy.
