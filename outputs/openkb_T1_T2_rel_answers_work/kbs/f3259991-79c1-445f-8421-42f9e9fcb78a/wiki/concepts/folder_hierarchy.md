# Folder Hierarchy

The **Folder Hierarchy** concept defines a lightweight, high‑level folder scaffold that supports easy file categorisation and long‑term maintenance. It originates from the guidance in [[summaries/session-10_2025-06-15]].

## Recommended top‑level buckets

- [[entities/work]] – job‑related documents, active projects; excludes personal items.
- [[entities/personal]] – life admin, hobbies; excludes work‑related files.
- [[entities/finances]] – money‑related records; excludes generic paperwork.
- [[entities/media]] – photos, videos, audio; excludes text documents.
- [[entities/reference]] – stable information you keep for later; excludes active projects.
- [[entities/archive]] – completed or inactive items; excludes anything you still use.
- [[entities/apps_utilities]] – installers, scripts, technical odds‑and‑ends; excludes work output.

## Boundary rules

Each bucket has a simple “what does not belong” rule to prevent overlap. For example, anything that is purely personal should never be placed under [[entities/work]], and media files should stay inside [[entities/media]] rather than in reference or work folders.

## Interaction with other concepts

- **Inbox management**: An empty **Downloads** or **Inbox** folder is kept as a temporary staging area; items are moved into the appropriate bucket immediately. See [[concepts/inbox_management]] for the processing routine.
- **Naming conventions**: Consistent folder and file names such as `ProjectName_YYYY‑MM` or `Category_Description_YYYY‑MM‑DD` support quick sorting and retrieval. See [[concepts/naming_conventions]].

## Workflow snapshot

1. Sketch the top‑level buckets.
2. As files appear, place them directly into the appropriate bucket or a sub‑folder.
3. When a project completes, move the whole project folder from [[entities/work]]/Projects to [[entities/archive]] (or a sub‑folder therein) rather than duplicating files.

By following this hierarchy, users obtain a clear backbone that can evolve without becoming a tangled maze.
